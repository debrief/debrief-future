### Field-by-field disagreement (before)

| Field | Generated TS | Writer's TS | Components' TS | Schema (LinkML) | Runtime validator |
|---|---|---|---|---|---|
| `activity_id` | `string` | `readonly string` | `string` | `string`, required | `typeof === 'string' && length > 0` |
| `timestamp` | `string` | `readonly string` | `string` | `string`, required | `typeof === 'string'` |

Three TS shapes, one schema, one runtime validator — and the writer's `source` enum admits two values nobody actually uses (`'tool'`, `'import'` are dead code; runtime validator rejects them).

## After — one canonical body + hybrid intersection + re-export

### 1. `shared/schemas/src/generated/typescript/types.ts:1600` — UNCHANGED

Same generated body as before. Now actually consumed.

### 2. `shared/components/src/PropertiesPanel/provenanceTypes.ts` — REPLACED with hybrid intersection

```typescript
import type { PropertiesProvenanceEntry as Generated } from '@debrief/schemas';

export const PROPERTIES_PANEL_TOOL_SENTINEL = 'debrief.propertiesPanel' as const;

/**
 * Per-commit provenance entry for the Properties Panel.
 *
 * Inherits `activity_id`, `timestamp`, `fields` from the LinkML-generated type;
 * narrows `tool`, `method`, `source` to the literal forms that today's
 * production write sites (stacService.ts, stacWriterIdb.ts) rely on for
 * compile-time typo detection.
 */
export type PropertiesProvenanceEntry =
  Omit<Generated, 'tool' | 'method' | 'source'> &
  {
    tool: typeof PROPERTIES_PANEL_TOOL_SENTINEL;
    method: `properties-panel@${string}`;
    source: 'user';
  };
```
