# Contract: LinkML `Tool` Schema Additions

**Feature**: 207-tool-manifest-categories
**File under change**: `shared/schemas/src/linkml/tool.yaml`

## New enum: `ToolCategoryEnum`

```yaml
enums:
  ToolCategoryEnum:
    description: >-
      Visual category for Log Panel icon rendering. Declared by the tool
      at registration; consumed by frontends to colour tool-icon glyphs.
      See docs/log-panel-ux-srd.md §5.

      This enum defines only the declarable values. The neutral-grey
      "unknown" state shown by the Log Panel when a tool has no declared
      category is NOT a value of this enum — it is a rendering-layer
      fallback produced when the attribute is null or absent.
    permissible_values:
      import:
        description: File / data ingestion tools (e.g., REP loader, DPF parser)
      style:
        description: Appearance-changing tools (e.g., set-track-color, symbol style)
      calc:
        description: Analytical computation tools (e.g., range-bearing, interpolate)
      filter:
        description: Tools that narrow the dataset (time filter, spatial filter, trim)
      snapshot:
        description: Tools that export or capture state (export-png, export-csv)
```

## Modified class: `Tool.category`

Added to the existing `Tool` class in the same file:

```yaml
  Tool:
    attributes:
      # --- existing attributes unchanged: id, name, description, version, requirements ---
      category:
        description: >-
          Visual category for Log Panel icon rendering. Null / absent
          tools render with the neutral-grey "Other" icon. First-party
          tools MUST declare a value (enforced by test policy; see
          specs/207-tool-manifest-categories/research.md §R5).
        range: ToolCategoryEnum
        required: false
```

## Schema adherence tests

A new fixture under `shared/schemas/fixtures/tool/` covers:

| Fixture | Expected result |
|---|---|
| `tool-with-category-import.valid.json` | Accepts `category: "import"` |
| `tool-with-category-null.valid.json` | Accepts `category: null` |
| `tool-without-category.valid.json` | Accepts omitted `category` field |
| `tool-with-invalid-category.invalid.json` | Rejects `category: "geometry"` |

Round-trip test: Python → JSON → TypeScript → JSON → Python preserves the `category` value (including null).

## Backwards compatibility

- Adding an optional enumerated attribute is backwards compatible: existing `Tool` instances with no `category` remain valid.
- The `debrief:category` annotation (hierarchical path, e.g. `track/styling`) is NOT part of the LinkML `Tool` class and is untouched by this contract. It continues to be derived by `Tool.to_mcp_tool()._derive_category()` exactly as today.

## Version bump

Per Article XIV (pre-release freedom), no schema version bump is required. The `shared/schemas` package version remains at its current value. Changelog entry documents the additive change.
