# Contract — PWA manifest

The Backlog Navigator emits a single `manifest.webmanifest` file at build
time, generated by `vite-plugin-pwa` from a typed config in
`vite.config.ts`. This document is the contract: every field below is
required for the Lighthouse PWA audit to score ≥ 90 (FR-022, SC-006).

## Output path

- **File**: `dist/manifest.webmanifest` (relative to the build output root)
- **Linked from**: `<link rel="manifest" href="/manifest.webmanifest">` in `index.html` (auto-injected by `vite-plugin-pwa`)
- **Content-Type served**: `application/manifest+json` (the host's preview/static-server config; verified in CI)

## Required fields

```json
{
  "name": "Debrief Backlog Navigator",
  "short_name": "Backlog",
  "description": "Edit the Debrief project backlog from any device.",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "orientation": "any",
  "theme_color": "#1f1f1f",
  "background_color": "#ffffff",
  "icons": [
    {
      "src": "/icon-192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any maskable"
    },
    {
      "src": "/icon-512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "any maskable"
    }
  ]
}
```

### Field-by-field invariants

| Field | Required | Invariant |
|-------|----------|-----------|
| `name` | Yes | Non-empty string. Used as the install dialog title and on Android home-screen long-press menus. |
| `short_name` | Yes | ≤ 12 characters. Used as the home-screen label on small icon grids. |
| `description` | Yes | Non-empty. Surfaced in the Android install dialog and PWA stores. |
| `start_url` | Yes | Must be absolute or root-relative. We use `/` so installs always open the navigator's root route. |
| `scope` | Yes | Must be a prefix of `start_url`. `/` covers the entire origin. |
| `display` | Yes | **Must be `"standalone"`** to remove browser chrome (User Story 5 acceptance #2). |
| `orientation` | Yes | `"any"` — the mobile layout adapts to portrait and landscape. |
| `theme_color` | Yes | Hex string. Drives the iOS status-bar tint and Android task-switcher card colour. Matches the navigator's existing dark header colour. |
| `background_color` | Yes | Hex string. Used by the OS for the splash background while the JS bundle is loading. |
| `icons[]` | Yes | Must contain at least one 192×192 and one 512×512 entry, both with `purpose` containing `any` and `maskable`. |

### Forbidden fields (for v1)

These manifest fields are **not** emitted; adding them is out of scope:

- `categories`, `screenshots`, `share_target`, `shortcuts`,
  `related_applications`, `prefer_related_applications`,
  `dir`, `lang`, `iarc_rating_id`.

If a future feature needs any of these (e.g. `share_target` for
"share to backlog"), a new spec opens.

## iOS-specific augmentation

iOS Safari ignores most manifest fields and reads `<link>` and `<meta>` tags
from the served HTML. `index.html` MUST include:

```html
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="apple-mobile-web-app-title" content="Backlog">
<meta name="theme-color" content="#1f1f1f">
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

The `viewport-fit=cover` is **mandatory** for `env(safe-area-inset-*)` to
return non-zero values on iPhone X+ (needed by the sticky push bar — R-8).

## Validation

A boundary Zod schema in `src/pwa/manifestSchema.ts` validates the typed
config object **before** `vite-plugin-pwa` consumes it. Build fails if the
schema rejects the config — preventing accidental regressions.

The Lighthouse CI workflow (R-10) re-validates the *emitted* manifest
against the same schema to catch plugin-version drift.

## Versioning

The manifest itself is unversioned (no `version` field — manifests don't
have one). Manifest changes ride along with the navigator's deploy; the
service worker (R-3) handles the update lifecycle and prompts the user.
