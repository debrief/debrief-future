# Phase 1 Data Model: Knip Configuration, Dev Dependency, and Verification Record

This feature introduces no runtime data structures. The "data model" here captures the configuration/documentation entities it produces and the one source-file deletion it performs.

## Entity 1: `knip.json` (repository-root configuration)

**Purpose**: Tell the unused-code scanner (`knip`) which source files are reachable entry points for each workspace that needs entry-point declarations. Currently only `apps/loader` needs one.

**Location**: `/knip.json` (repository root).

**Shape** (normative schema in [contracts/knip-config.schema.json](./contracts/knip-config.schema.json)):

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `$schema` | `string` (URL) | Yes | Pointer to knip's published JSON Schema, pinned to major version 5. Editor-hint only; no runtime effect on knip. |
| `workspaces` | `object` | Yes | Map keyed by workspace path (relative to repo root). Only workspaces needing entry-point overrides appear here. |
| `workspaces["apps/loader"]` | `object` | Yes | Loader-specific entry declarations. |
| `workspaces["apps/loader"].entry` | `string[]` | Yes | Source paths (relative to workspace root) treated as reachable roots. |

**Validation rules**:
- `$schema` MUST pin a major version (not `@latest`).
- `workspaces["apps/loader"].entry` MUST contain exactly three paths:
  - `src/main/index.ts` — Electron main-process entry.
  - `src/preload/index.ts` — Electron preload entry.
  - `src/main.tsx` — Vite renderer entry.
- No `ignore`, `ignoreDependencies`, or workspace-wide `project` override is permitted at this feature's completion (enforces FR-004, FR-005, FR-008). When #199 lands, the contract relaxes to allow a tightly enum-whitelisted `ignore` — see research.md R-007.
- No other workspace key may appear under `workspaces` at this feature's completion — scope guard per FR-005.

**State transitions**: None. The file either exists with the required shape or it does not.

**Relationship to other entities**:
- Consumed by `knip` (invoked via `pnpm exec knip` from `task knip`).
- References source files in `apps/loader/src/` — the domain, out of scope for this section.

## Entity 2: Root `package.json` `devDependencies` entry

**Purpose**: Pin `knip` as a reproducible dev dependency now that it is a required CI gate (Article I.4, Article IX.2).

**Location**: `/package.json` under `devDependencies`.

**Shape**: one new entry, string-valued SemVer specifier pinned to a specific 5.x version current at implementation time.

```jsonc
{
  "devDependencies": {
    "@playwright/test": "^1.58.0",
    "@sparticuz/chromium": "^143.0.4",
    "knip": "^5.x.y",          // NEW — pick exact 5.x version at implementation
    "tsx": "^4.7.0"
  }
}
```

**Validation rules**:
- MUST be a caret-pinned 5.x specifier (`^5.x.y`), not `latest`, not `next`, not a range spanning majors.
- The exact version chosen MUST be captured in the verification record (Entity 4 § 5).
- `pnpm-lock.yaml` MUST be regenerated by `pnpm install` as part of the commit.

**Relationship to other entities**:
- Consumed by `pnpm exec knip` (locally and in CI).
- Drives the `task knip` Taskfile target (Entity 3).

## Entity 3: `task knip` target + CI step

**Purpose**: Provide a single canonical entry point for running knip in both local developer workflow (`task verify`) and CI (`.github/workflows/ci.yml`). Eliminate the ad-hoc `pnpm dlx knip` invocation.

**Location**: `/Taskfile.yml` and `/.github/workflows/ci.yml`.

### 3a. Taskfile target

```yaml
knip:
  desc: "Run knip — fail if any non-declared unused files are detected"
  deps: [install]
  cmds:
    - pnpm exec knip
```

Plus a line appended to `task verify`'s `cmds`:
```yaml
    - task: knip
```

**Validation rules**:
- The target name MUST be `knip` (top-level, not nested under `lint:*`) — see research.md R-008.
- `task verify` MUST include `task: knip` after `task: test` (keeps the existing lint → typecheck → test ordering intact).
- No network fetch beyond the `deps: [install]` step. Running `task knip` on a machine with `pnpm install` already done MUST NOT hit the network.

### 3b. CI step

A new step in `.github/workflows/ci.yml`, inserted after "Run linting":

```yaml
      - name: Run knip
        run: task knip
```

**Validation rules**:
- Step MUST run after the existing `Run linting` step and before or parallel to `Run type checking`.
- Step MUST NOT introduce new external service dependencies (the dep is already satisfied by `task install`).
- A failure of this step MUST fail the whole CI workflow (same semantics as the existing lint / typecheck / test steps).

## Entity 4: Verification Record (`evidence/verification-record.md`)

**Purpose**: Satisfy FR-007 — a short, auditable written artefact a future maintainer can read in under five minutes (SC-006) to confirm the whitelist's premise is still valid.

**Location**: `specs/201-knip-loader-config/evidence/verification-record.md`.

**Shape**: Markdown document with these required sections:

| Section | Content |
|---------|---------|
| Front matter (YAML) | `git_sha`, `captured_at` per `.specify/templates/evidence/test-summary-template.md`. |
| **1. Scope** | One sentence: "Verification record for feature #201 / backlog #202 — knip config for apps/loader, with CI gate and updater.ts deletion." |
| **2. Declared Entry Point(s)** | Bullet list of the three entry paths (copied verbatim from `knip.json`). |
| **3. Reachability Confirmation** | Table with one row per previously-flagged file, two columns: file path, outcome (✅ reachable via [import chain] / 🗑 DELETED). `updater.ts` row marked DELETED. |
| **4. Genuine Orphans Remaining** | Expected content: "None — `updater.ts` was the only genuine orphan and has been deleted." If a future audit finds a new orphan, update this section. |
| **5. Dev Dependency Version Pinned** | The exact `knip` version pinned in `package.json` (e.g., `^5.20.0`). |
| **6. Build Smoke** | Command run (`pnpm --filter debrief-loader build:main`) + exit status + one-line summary. |
| **7. Pre/Post Knip Output** | Two short code blocks: (a) file count under `apps/loader/src/main/**` flagged BEFORE the feature, (b) same count AFTER. Expected: `12 → 0`. |
| **8. Non-loader Findings Unchanged** | Diff output (or link to a stored diff artefact) showing non-loader portion of knip output is unchanged. Confirms SC-002. |
| **9. CI Gate Exercised** | Confirmation that a trial PR (or local `task verify`) ran the new CI step and it passed on the clean state AND failed when a dummy orphan was temporarily introduced (stress test). |

**Validation rules**:
- All nine sections MUST be present.
- Section 4 at this feature's completion is exactly "None — `updater.ts` was the only genuine orphan and has been deleted." Any future update to this file that changes Section 4 to list a remaining orphan is itself a regression signal.
- Section 9 MUST include either the CI run URL OR a transcript of a local `task verify` run, plus the result of the stress test (SC-005 coverage).

**State transitions**: Produced once during implementation; amended in future only if the whitelist changes (e.g., #199 adds `ignore` for `specs/**`). Git history is the full audit trail.

## Entity 5: `apps/loader/src/main/updater.ts` (deletion)

**Purpose**: Remove the one file under `apps/loader/src/main/` that is NOT reachable from the declared entry. Required to make SC-001 ("12 → 0") hold without resorting to `ignore` globs (FR-004, FR-008).

**Shape (before deletion)**: An 80-line TypeScript file containing:
- A commented-out import: `// import { autoUpdater } from 'electron-updater';`
- A stub `checkForUpdates()` function with no call sites.
- No inbound imports (verified by `grep -rn updater apps/loader/src`).

**Validation rules for the deletion**:
- `git rm apps/loader/src/main/updater.ts` MUST complete cleanly (no dependents).
- `pnpm --filter debrief-loader build:main` MUST still succeed after deletion.
- `pnpm --filter debrief-loader test` MUST still succeed (no tests reference `updater.ts` — verified before commit).
- The commit message MUST note "deleted as part of #202 knip cleanup — genuine orphan, no call sites; auto-update is a separate future feature if needed."

## Out of Scope (not modelled)

- Knip's own internal report format — consumed as opaque text; only "file counts under the loader tree" and "non-loader findings unchanged" are extracted for verification.
- `apps/loader/package.json` — unchanged by this feature.
- The loader source tree beyond the one `updater.ts` deletion — unchanged by this feature.
- Adding entry declarations for other workspaces (vscode, web-shell, spec-navigator, components, etc.) — deferred until a scan surfaces noise there.
- Auto-update feature wiring for Electron — explicitly out of scope (would require `electron-updater` dep, signing keys, update server; separate feature).
- Item #199's `ignore: ["specs/**"]` addition — coordination note only (research.md R-007).
