### `shared/components/e2e/LogPanelA11y.spec.ts`

Six stories × three themes = 18 Playwright/axe runs:

| Story ID | Themes |
|---------|--------|
| `logpanel--timeline-default` | light, dark, vscode |
| `logpanel--empty-no-plot` | light, dark, vscode |
| `logpanel--empty-no-entries` | light, dark, vscode |
| `logpanel--entry-selected` | light, dark, vscode |
| `logpanel--compact-view` | light, dark, vscode |
| `logpanel--flip-card-default` | light, dark, vscode |

Each run:
- Loads the story with `?globals=theme:<variant>`.
- Runs an optional pre-audit interaction (click-to-select for
  `entry-selected`; flip-to-edit for `flip-card-default`).
- Executes `AxeBuilder` with the `wcag2a|wcag2aa|wcag21a|wcag21aa` tag set.
- Accumulates violations and writes the aggregated report in `afterAll`.

The `afterAll` asserts `critical + serious === 0`.

## Key scenarios verified (in authored code)

- Synthetic `--vscode-*` variables are only injected outside VS Code webviews
  (the `isVSCodeEnvironment()` guard keeps production behaviour untouched).
- Switching the Storybook theme globals re-applies the matching variant
  values with one render cycle (useEffect dependency is `resolvedVariant`).
- The vscode variant STRIPS any previously-injected inline values so the real
  VS Code host variables can supply the style cascade cleanly.
- Required keys of the `VS_CODE_TOKEN_MAP` stay in structural parity across
  `light` and `dark` via a unit-test-enforced union.
