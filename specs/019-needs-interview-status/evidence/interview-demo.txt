# Demo: /interview Command

This demonstrates the batch interview processing workflow.

## Command (List Mode)

```
Human: /interview
```

## Expected Output (List of Pending Items)

```
## Items Awaiting Interview

| # | ID | Category | Description | Prelim Scores |
|---|----|-----------|--------------|----|
| 1 | 042 | Feature | Add batch export feature for reports | V:4 M:3 A:4 |
| 2 | 045 | Enhancement | Improve search performance | V:4 M:2 A:3 |

**Select an item by ID** (e.g., `042`) or **number** (e.g., `1`)

Or run `/interview {ID}` directly to skip this step.
```

## Command (Direct Selection)

```
Human: /interview 042
```

## Expected Interview Flow

The interview uses multiple-choice questions asked one at a time:

```
What is the primary use case for batch export?

A) Exporting multiple analyses for external reporting
B) Archiving completed projects
C) Sharing with team members who don't have Debrief
D) Other (please describe)
```

User answers, then next question:

```
What file formats should be supported?

A) PDF only (for formal reports)
B) PDF and CSV (reports + data)
C) PDF, CSV, and GeoJSON (full data portability)
D) User-configurable format selection
```

## Edge Case: No Items

```
Human: /interview
```

```
## Interview Queue Empty

No items have status `needs-interview`.

**To add items for later interview:**
- Use `/idea --defer {description}` for quick capture
- Items will appear here for detailed requirements gathering
```

## Key Points Verified

1. Step 1 parses BACKLOG.md for needs-interview items
2. Step 2 displays numbered list with selection options
3. Step 3 accepts ID or list number selection
4. Step 4 uses multiple-choice questions (FR-009, FR-010)
5. Step 5 creates GitHub issue
6. Step 6 updates status to proposed
7. Step 7 refines scores
8. Step 8 performs strategic review
