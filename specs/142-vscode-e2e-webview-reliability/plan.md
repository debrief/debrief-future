# Implementation Plan: VS Code E2E Webview Reliability

**Branch**: `142-vscode-e2e-webview-reliability` | **Date**: 2026-03-18 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/142-vscode-e2e-webview-reliability/spec.md`

## Summary

Research sprint to identify and fix the root cause of `resolveWebviewView` never firing in openvscode-server's headless Playwright environment, then unskip at least 5 of the ~15 self-skipping VS Code E2E test files. The approach prioritises low-effort solutions (forced view reveal via command, openvscode-server upgrade) before high-effort ones (workbench.js patching, real VS Code in xvfb).

## Implementation Phases

### Phase 1: Root Cause Investigation (US1)

**Goal**: Identify exactly why `resolveWebviewView` is never called.

1. **Set up diagnostic environment**: Add console logging to `global-setup.ts` to capture extension activation events
2. **Test view reveal command**: Try `workbench.view.extension.debrief-sidebar` via command palette in Playwright to force view container visibility
3. **Inspect workbench.js**: Search for the webview view resolution code path and identify the visibility gate
4. **Test openvscode-server upgrade**: Try latest stable release to see if the issue is fixed upstream
5. **Document findings**: Update `docs/project_notes/webview-e2e-research.md` with root cause evidence

### Phase 2: Solution Validation (US2)

**Goal**: Get one previously-skipped test passing with real extension content.

Based on research priority order:

1. **Approach E (view reveal command)**: Modify `CodeServerPage.openPlotViaStacTree()` to first execute the sidebar reveal command, then wait for webview resolution
2. **Approach B (upgrade)**: If E alone is insufficient, upgrade openvscode-server and retest
3. **Approach A (patch)**: If upgrade doesn't fix it, add a fourth patch to `patch-webview.sh` targeting the resolution gate
4. **Approach D (xvfb + real VS Code)**: If patching is unreliable, set up real VS Code under xvfb

Validation target: `test-load-display.spec.ts` passes with real extension MapView content visible.

### Phase 3: Test Suite Activation (US3)

**Goal**: Unskip at least 5 test files and update CI.

1. Remove `test.skip()` annotations from validated test files
2. Convert tests with legitimately missing features to `test.fixme()` with backlog references
3. Update `e2e.yml` workflow with new openvscode-server version (if upgraded) and updated patches
4. Verify full suite passes in CI-like conditions (headless, xvfb)

### Phase 4: Polish & Evidence

**Goal**: Document the solution and capture evidence.

1. Update `docs/project_notes/webview-e2e-research.md` with complete resolution
2. Capture screenshots of real webview content in Playwright
3. Create evidence artifacts (test-summary.md, usage-example.md)
4. Create media content (shipped post, LinkedIn)
