## Phase 2 — AuditWriter service (US1 foundation)

- [ ] T010 Create `apps/vscode/src/services/auditWriter.ts`. Module-scoped state: `config: AuditConfig`, `channel: vscode.OutputChannel | null`, `fileStream: fs.WriteStream | null`, `sessionId: string`, `knownCredentialSubstrings: Set<string>`, `suppressFileForSession: boolean`.
- [ ] T011 Implement `configureAuditWriter(config: AuditConfig): void`: close any prior file stream, recreate channel/stream to match new config. Called at extension activation and on every relevant settings change.
- [ ] T012 Implement `writeAuditRecord(record: AuditRecordInput): void`: early-return when `config.enabled === false`; else build the full `AuditRecord`, run the credential-scrub post-serialise gate, emit to channel (`channel.appendLine(serialised)`) and optional file stream (`fileStream.write(serialised + "\n")`).
- [ ] T013 Implement an inline ULID generator for `submission_id` (Crockford base32, 10 chars time + 16 chars random). ~20 lines. No new dependency.
- [ ] T014 Implement SHA-256 hashing via Node stdlib `crypto.createHash("sha256").update(bytes).digest("hex")`. Prompt + response are canonical UTF-8 bytes.
- [ ] T015 Implement credential scrubbing: before emit, run `serialised.includes(candidate)` for each known credential substring. On match, replace the record with `{ outcome: "audit-credential-scrub-triggered", submission_id, timestamp, session_id }` and log an error to the extension's primary log channel.
- [ ] T016 Implement file-unwriteable handling: on `fileStream.write` error, emit a single diagnostic record `{ outcome: "audit-file-unwriteable", path, error: errorName }` to the channel, close the stream, set `suppressFileForSession = true`. Subsequent writes skip the file.
- [ ] T017 Register `vscode.workspace.onDidChangeConfiguration` in `extension.ts` so changes to `debrief.nlSearch.audit.*` settings reconfigure the writer without a reload.

## Phase 3 — llmProxy integration (US1)

- [ ] T020 Edit `apps/vscode/src/services/llmProxy.ts` — after outcome classification (but before sending the `nlOutcome` webview message), call `writeAuditRecord({...})` with `submission_id` (generated by the writer if not supplied), `panel_origin` (from #195 if merged, else `"catalog-overview"`), `provider` + `providerModel` (from #196 if merged, else `anthropic` + current model), `outcome.kind`, `duration_ms`, `prompt`, `response`, `chips`.
- [ ] T021 Ensure that unhandled exceptions in `llmProxy.ts` are caught at the outermost level and converted to an audit record with `outcome: "unhandled-exception"` + `error_name` (no stack trace, no message content to avoid path disclosure).
- [ ] T022 Register `knownCredentialSubstrings` population: when `llmProxy.ts` loads a key from `SecretStorage`, notify `auditWriter` of the substring so the scrubber knows to check for it. Avoid logging or persisting the substring outside of the scrubber's memory.

## Phase 5 — User Story 2: Redaction (P2)

- [ ] T040 **[US2]** In `auditWriter.ts` `buildRecord(input, config)`: when `config.redactContent === true`, omit `prompt` and `response` fields. Always compute and include `prompt_hash` + `response_hash`.
- [ ] T041 **[US2] [P]** Unit test: toggling redaction mid-session causes the next record to omit content; prior records are not retroactively modified.
- [ ] T042 **[US2] [P]** Unit test: submitting identical phrase twice produces equal `prompt_hash` values in redacted records (hash identity property).

## Phase 6 — User Story 3: Reliability (P3)

- [ ] T050 **[US3]** Unit test in `auditWriter.test.ts` — "disabled mode produces zero observable effect": enable + write 10 records, reset to disabled, assert channel still exists BUT no further writes reach it. Also start a fresh writer in disabled state and assert `channel` is never created.
- [ ] T051 **[US3]** Unit test — "webview-reload safety": since AuditWriter lives in extension host and not webview, exercise a webview reload simulation (reinitialise the webview; prove the writer's state is unchanged).
- [ ] T052 **[US3]** Unit test — "provider-exception path writes audit record": inject an unhandled exception from the provider call; assert an `unhandled-exception` outcome appears in the audit stream.
- [ ] T053 **[US3]** Unit test — "100-submission soak": run 100 stubbed submissions covering success + seven failure classes. Assert 100 valid JSON Lines appear in the audit output, each parseable by `JSON.parse`, each with the complete field set per FR-003.
- [ ] T054 **[US3]** Unit test — "file-unwriteable produces one diagnostic record, no retry in-session": configure a read-only path; submit twice; assert exactly one `audit-file-unwriteable` record in the channel, no file written, subsequent file writes suppressed.

## Phase 7 — Credential scrubbing (US1 defence in depth)

- [ ] T060 Unit test — "credential-scrubber catches injected key": inject a fake API key `"sk-ant-test-DO-NOT-LEAK"` into the cached-credentials set; construct a record whose `response` contains that substring (via adversarial stub); assert the emitted record is `{ outcome: "audit-credential-scrub-triggered", ... }` with zero occurrences of the key substring.
- [ ] T061 Unit test — "scrubber checks every variant": inject three known substrings; confirm any match triggers the scrub path.
