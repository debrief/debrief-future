Documentation work often gets overlooked, but building complex systems means nothing if the next developer can't figure out how to use what you built.

We just shipped the Storybook VS Code theming guide—a comprehensive reference covering the three-layer theming architecture that powers Debrief's component system. It includes all 21 VS Code variable mappings, complete color token tables for light and dark modes, and concrete how-to examples for creating themed components.

The system itself was already solid. The gap was in documentation. Developers were piecing together the design from scattered comments and experimentation. Now they have a single source of truth: how variables map to tokens, which tokens control what, and exactly how to build components that respect the user's theme.

Good documentation doesn't rewrite working architecture—it makes the working architecture visible and usable. That's what we shipped.
