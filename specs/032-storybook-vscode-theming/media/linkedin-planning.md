Building components in a distributed team gets messy when theming documentation lives in people's heads.

We're working on a comprehensive guide that bridges our three-layer theming architecture: CSS tokens, VS Code's theme adapter, and React context. The catch? We're not hand-curating token lists—we're extracting reference tables directly from the source code so the documentation can't drift.

Here's what matters: a defence analyst contributes a component. They read the guide. They understand which tokens to use, why the architecture exists, and how dark mode behavior works. They submit code that's already correctly themed. That's a 10x improvement over reverse-engineering existing components.

We're targeting external audiences too—DSTL scientists, potential contributors, the wider maritime analysis community. Clear theming documentation is part of making that possible.
