## Design Decisions

### D1: Hook vs Component

**Decision**: `useGeoman` hook (not a `<GeomanControl />` component).

**Rationale**: The existing codebase uses `useMap()` hooks extensively. A hook gives consumers control over when Geoman is active without requiring a component in the JSX tree. The `createControlComponent` pattern from `@react-leaflet/core` is an alternative, but it ties Geoman initialization to component mounting — the hook is more flexible for the downstream E05 features that need conditional activation.

### D2: Opt-In Mode

**Decision**: Call `L.PM.setOptIn(true)` on Geoman import so Geoman does not auto-manage all layers.

**Rationale**: Without opt-in mode, Geoman automatically makes existing GeoJSON layers editable/draggable which would break existing track interaction behavior. Opt-in mode ensures only layers explicitly created through Geoman are managed by it.

### D3: CSS Import Location

**Decision**: Import Geoman CSS in `MapView.tsx` alongside the existing `import 'leaflet/dist/leaflet.css'`.

**Rationale**: This ensures Geoman CSS is available wherever MapView is used, matching the established pattern. The esbuild `--loader:.css=text` loader will inline it as a string, and the `'unsafe-inline'` CSP in the VS Code webview HTML allows injection. In Vite/Storybook, `vite-plugin-css-injected-by-js` handles it.

### D4: Toolbar Default State

**Decision**: Geoman toolbar is hidden by default. The `useGeoman` hook accepts options but does not call `map.pm.addControls()` unless the consumer explicitly opts in.

**Rationale**: This feature is infrastructure — later E05 features (#093) add the toolbar. Default-off ensures no visual changes to existing MapView usage.
