# Quickstart: NL → CQL2 Prompt Design + Generation

**Feature**: 188-nl-cql2-prompt

This document is the "how do I actually run this" reference for anyone touching the feature after it lands — implementors, reviewers, and later items (#189 transport, #190 demo UI).

## Prerequisites

All three of these must be in place (they already are — verified on 2026-04-14):

- `shared/data/enum-bundle.json` — produced by item #187.
- `shared/data/platform-registry.json` — produced by item #180.
- `preview/workspace/samples/local-store/catalog.json` plus referenced items — regenerated by item #184.

The `filter-engine` module (`shared/components/src/filter-engine/`) with `array_filter` evaluation (item #185) must be on the current branch.

## Run the regression harness (default / CI path)

Uses `RecordedLLMClient` — fully offline, deterministic.

```sh
# From repo root
pnpm --filter @debrief/components test

# Just the corpus suite
pnpm --filter @debrief/components test:nl-corpus
```

Passes when every phrase in `fixtures/corpus.json` produces CQL2 that, when evaluated against the sample catalog, matches the expected `matchCount` / `matchIds` / `unrecognisedTerms` declared on that phrase.

Failure output (per phrase) includes:

- Phrase text and corpus `id`.
- The CQL2 produced by the generator (or `null` if parsing failed).
- Expected vs. actual match count.
- The raw LLM response (when present — `RecordedLLMClient` always has one; live mode also captures it).

## Record or re-record fixtures (authoring path)

When you change the prompt template, the schema description, or the enum bundle, the recorded responses may be stale. Re-record them.

```sh
# Pseudocode — the actual script is shared/components/scripts/record-nl-fixtures.ts
pnpm --filter @debrief/components record-nl-fixtures --corpus src/nl-cql2/fixtures/corpus.json
```

The script:

1. Loads the corpus.
2. For each phrase, builds the current prompt.
3. Calls a `PassthroughLLMClient` wrapping whatever LLM you have on hand (pluggable — see `scripts/record-nl-fixtures.ts`).
4. Writes the raw responses + their prompt hashes into `fixtures/responses.json`.

After re-recording, run the harness (`pnpm test:nl-corpus`) to confirm the new fixtures still pass against the expected match counts. If a recorded response now produces different match counts, that is a prompt regression — investigate before committing.

## Add a new analyst phrase

1. Add an entry to `shared/components/src/nl-cql2/fixtures/corpus.json`:

   ```jsonc
   {
     "id": "uk-destroyers",
     "phrase": "British destroyers",
     "expected": { "matchCount": null },
     "notes": "New phrase; expected count to be recorded"
   }
   ```

2. Record the fixture (see above). During first record, the response is captured but the expected count is still `null`, so the harness will PASS without asserting on count.
3. Inspect the recorded CQL2 + the match count it produces (visible in harness output or by running the script manually).
4. If the count is correct, update `expected.matchCount` in `corpus.json` to lock the baseline. Commit both files together.

## Consume the generator from downstream items

Item #189 (transport) and item #190 (demo UI) import the module like this:

```typescript
import {
  generateCql2,
  createPassthroughLLMClient,
  type GenerationResult,
} from "@debrief/components/nl-cql2";
import enums from "@debrief/shared-data/enum-bundle.json"; // via existing debrief-data access

const client = createPassthroughLLMClient(async (prompt) => {
  // #189 plugs in MCP / HTTP / local here
  return await someTransport(prompt);
});

const result: GenerationResult = await generateCql2("UK submarines", {
  enums,
  client,
});
```

The returned `result.cql2` can be fed directly into `createFilterEngine(...).evaluate(result.cql2)` to filter the catalog. `result.chips` drives the filter bar UI. `result.unrecognisedTerms` drives the empty-state hint in #190.

## What "done" looks like for this item

- `pnpm test:nl-corpus` green — all 9+ corpus phrases pass.
- `task verify` green on the feature branch (lint + typecheck + test).
- Prompt size under 20 KB (asserted by the harness via `report.promptSizeBytes`).
- No `any` anywhere in the new module (`tsc --noEmit` + the project's strict settings catch this).
- A deliberate regression (e.g. stub `schemaDescription()` to return `""`) reliably causes at least one phrase to FAIL with a readable diagnostic — this is SC-006 and should be exercised manually once.

## What this item does NOT do

- Ship a real LLM transport — that is #189. This item only accepts a transport.
- Ship a UI — that is #190. This item only produces data the UI will consume.
- Modify the filter-engine, LinkML schemas, platform registry, or the sample catalog.
- Handle non-English phrases, NL search history, or prompt caching.
