# Feature Specification: Schema-Rooted DisplayMode and PlaybackState Enums

**Feature Branch**: `205-displaymode-playbackstate-linkml`
**Created**: 2026-04-21
**Status**: Draft
**Input**: Backlog item #205 (Tech Debt) — Promote `DisplayMode` and `PlaybackState` to LinkML and eliminate hand-typed TS duplicates with drifted vocabularies. Source: `docs/ideas/205-displaymode-playbackstate-linkml.md`.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Single schema-rooted vocabulary end to end (Priority: P1)

A developer writing code that touches track display mode or playback state — anywhere across the VS Code extension, the web shell, the shared component library, or the session-state store — imports `DisplayModeEnum` and `PlaybackStateEnum` from `@debrief/schemas` (TypeScript) or `debrief_schemas` (Python). One vocabulary per concept, generated from the LinkML master schema, consistent across Python, TypeScript, and JSON Schema. No `'full'|'trail'` vs `'normal'|'snailTrail'` coin-flip when wiring up a new message; no `'playing'|'paused'` vs `'stopped'|'playing'|'paused'` mismatch when reading session state from the component side.

**Why this priority**: This is the core outcome — without a canonical, schema-rooted vocabulary each side of the boundary, every downstream deletion and translator-removal has nothing to migrate to. All other stories depend on these generated types being the single source of truth.

**Independent Test**: Regenerate Pydantic + TypeScript from the updated LinkML schema. Import `DisplayModeEnum` and `PlaybackStateEnum` from `@debrief/schemas`, and their Pydantic equivalents from `debrief_schemas`. Construct a `TemporalSlice`-like value using every enum value (`full`, `trail`; `stopped`, `playing`, `paused`) and confirm both languages accept it without casts. Schema round-trip tests pass.

**Acceptance Scenarios**:

1. **Given** the updated LinkML schema and freshly regenerated artefacts, **When** a developer writes `import { DisplayModeEnum, PlaybackStateEnum } from '@debrief/schemas'`, **Then** both enums exist, are exported from the package barrel, and expose the canonical permissible values (`DisplayModeEnum` → `full`, `trail`; `PlaybackStateEnum` → `stopped`, `playing`, `paused`).
2. **Given** the generated Pydantic models for `PlaybackStateEnum` and `DisplayModeEnum`, **When** Pydantic validates canonical fixtures covering every permissible value, **Then** all fixtures validate successfully and invalid values (e.g., a legacy `'snailTrail'` string or a misspelling) are rejected.
3. **Given** a value of type `DisplayModeEnum` on the Python side, **When** it is JSON-serialised and re-parsed on the TypeScript side (and vice versa), **Then** the value round-trips byte-identically through the existing schema round-trip fixture suite.
4. **Given** any consumer package (`@debrief/components`, `@debrief/session-state`, `apps/vscode`, `apps/web-shell`), **When** the package imports the generated enum type, **Then** TypeScript treats the value as a string-literal union (or equivalent generated form) with the canonical members and no other values.

### User Story 2 — Clean deletion of hand-typed copies and translator sites (Priority: P2)

A maintainer reviewing `shared/components/src/utils/types.ts`, `shared/components/src/TimeController/types.ts`, and `services/session-state/src/types/temporal.ts` finds **zero** hand-written `export type DisplayMode = ...` or `export type PlaybackState = ...` declarations. Every former consumer (TimeController, DisplayModeToggle, PlaybackControls, TemporalTrackLayer, session-state store, activity panel host view, time range host view, web-shell App shell) imports the generated enum directly. The ad-hoc translation ternaries that today appear at least seven times across `apps/vscode/src/views/activityPanelView.ts`, `apps/vscode/src/views/timeRangeView.ts`, `apps/vscode/src/webview/mapPanel.ts`, and `apps/web-shell/src/App.tsx` (`m === 'snailTrail' ? 'trail' : 'full'`, `m === 'trail' ? 'snailTrail' : 'normal'`) are gone. No local `toComponentMode` / `toStoreMode` helpers remain.

**Why this priority**: This is the tech-debt payoff. Deleting the duplicates and the scattered translators is what removes the drift and eliminates the 7+ sites a reader has to keep in their head when tracing `displayMode` across the IPC boundary. It depends on Story 1 because consumers can only migrate after the canonical enums exist.

**Independent Test**: Run `grep -rE '^(export\s+)?type\s+(DisplayMode|PlaybackState)\b' apps/ shared/ services/` on the post-change tree (excluding generated artefacts) and confirm zero matches. Run `grep -rnE "'snailTrail'\s*\?|'normal'\s*\?|=== 'trail'|=== 'full'" apps/ shared/ --include='*.ts' --include='*.tsx'` and confirm the legacy translation patterns are gone. Run the full `task verify` pipeline and confirm all packages build with no type errors after the migration.

**Acceptance Scenarios**:

1. **Given** the post-change codebase, **When** a reviewer searches for hand-written `type DisplayMode` or `type PlaybackState` declarations in `apps/`, `shared/`, and `services/`, **Then** no matches are found outside `shared/schemas/src/generated/`.
2. **Given** the post-change codebase, **When** a reviewer searches for the legacy ternary translation pattern between `'normal'|'snailTrail'` and `'full'|'trail'`, **Then** no matches are found in application code (the identity mapping replaces them — both sides now speak `full|trail`).
3. **Given** `apps/web-shell/src/App.tsx`, **When** a reviewer inspects the top of the file, **Then** the `toComponentMode` / `toStoreMode` helper functions and their accompanying comment (`// Map between session-state DisplayMode ... — the two enums diverged historically.`) are deleted, and the call sites pass the store value directly to component props.
4. **Given** every former consumer of the deleted types, **When** `pnpm -r typecheck` and `uv run pyright` run, **Then** both complete without errors attributable to the migration.
5. **Given** the existing unit test suites for `useTimePlayback`, the session-state `TemporalSlice`, and the TimeController Storybook stories, **When** they run against the post-change code, **Then** all tests pass; any test-side edits are limited to swapping the imported enum name / members, not rewriting assertions.

### User Story 3 — Guard rails and the documented `stopped` UI rule (Priority: P3)

A future contributor building a new temporal UI does not re-introduce a hand-typed `'playing'|'paused'` shortcut because the canonical `PlaybackStateEnum` is the type their IDE suggests from `@debrief/schemas`. They find a documented rule for how the component layer treats `stopped`: render identically to `paused` (no trail animation, no playhead motion, play button enabled, pause button disabled), because components originally knew only two states and the third is widened-in by this feature. The commit that performs the consolidation records the rationale in `docs/project_notes/decisions.md` so the memory-aware review protocol (CLAUDE.md) surfaces the decision on future reviews.

**Why this priority**: Guard rails make the fix durable. Without the documented `stopped` UI rule the migration works today but is under-specified for the next developer who touches `PlaybackControls` or `useTimePlayback`; without the ADR the reason for the vocabulary choice is lost the moment the PR scrolls off the history view. Lower than P1/P2 because the immediate consolidation captures the lion's share of the value even without documentation.

**Independent Test**: Inspect `docs/project_notes/decisions.md` for a dated ADR entry that (a) names the four deleted hand-typed declarations and their drifted vocabularies, (b) records the canonical vocabulary chosen for each enum and why, (c) states the `stopped ≡ paused` rendering rule. Inspect the generated TypeScript `PlaybackStateEnum` declaration for a docstring that either carries the `stopped ≡ paused` rendering rule directly or points to the ADR. Verify `shared/components/src/TimeController/PlaybackControls.tsx` handles `stopped` without a type error and without falling through to an `unreachable` branch.

**Acceptance Scenarios**:

1. **Given** `docs/project_notes/decisions.md` after merge, **When** a reviewer searches for entries relating to `DisplayMode`, `PlaybackState`, or LinkML enum consolidation, **Then** a dated ADR entry exists that names the deleted hand-typed types, records the canonical vocabulary for each enum, and documents the component-side `stopped ≡ paused` rendering rule.
2. **Given** the generated `PlaybackStateEnum` TypeScript declaration, **When** a reader opens the generated file or hovers the symbol in an IDE, **Then** the enum's docstring (sourced from the LinkML `description`) describes all three states and either carries the `stopped ≡ paused` rendering rule or explicitly references the ADR where the rule is documented.
3. **Given** a subsequent code-review on a PR that reintroduces a hand-typed `type PlaybackState = 'playing' | 'paused'`, **When** the reviewer invokes the project's memory-aware protocol, **Then** the ADR surfaces and the reviewer can quote the canonical pattern.

### Edge Cases

- **The LinkML `DisplayModeEnum` currently uses `normal|snailTrail`, not the canonical `full|trail`**: Today `shared/schemas/src/linkml/session-state.yaml` (lines 34–40) defines `DisplayModeEnum` with `normal` and `snailTrail`. This feature renames the permissible values to `full` and `trail` to match the component-side UI vocabulary (which is what a user sees on the `DisplayModeToggle` buttons: "Full" and "Trail"). The `PlaybackStateEnum` (`stopped|playing|paused`) is already canonical and does not change.
- **Persisted session-state fixtures with legacy `DisplayMode` values**: Any committed JSON fixtures, Storybook fixtures, or test fixtures with `"displayMode": "normal"` or `"displayMode": "snailTrail"` MUST be migrated in-place to `"full"` or `"trail"`. A full-tree search (`grep -r '"displayMode"' --include='*.json'`) found no matches at the time of spec writing; any new fixtures introduced between now and merge must follow the same rule.
- **Component-side `PlaybackState` widening to three states**: `shared/components/src/TimeController/useTimePlayback.ts` currently initialises `playbackState` as `'paused'` and `shared/components/src/ActivityPanel/types.ts` types a prop as `'playing' | 'paused'`. After the migration the component layer MUST accept the full three-state vocabulary; any narrowed local prop type MUST be widened or MUST explicitly document why the narrowing is correct (e.g., a transient UI variable that is never assigned `'stopped'`).
- **Component behaviour when `playbackState === 'stopped'`**: The component layer has never seen this value before because the `apps/vscode` host view's translator mapped `'stopped'` away. After the migration, components MUST render the `stopped` state identically to `paused` (static playhead at `currentTime`, no frame-rate animation, play button enabled to resume, pause button disabled or treated as a no-op). This rule is called out explicitly in the ADR and in the generated-enum docstring.
- **Discriminated-union loss in session-state TemporalSlice**: Today `services/session-state/src/types/temporal.ts` types `TemporalSlice.displayMode` and `TemporalSlice.playbackState` as discriminated string-literal unions with a comment ("discriminated union literals for type safety") explaining why it deliberately diverges from the generated schema. Post-migration the slice MUST import the generated enums; if the generated form is a named TS `enum` rather than a string-literal union, consumers keep literal-narrowing via the enum's members (`PlaybackStateEnum.playing`, etc.), and the slice's discriminated-union comment is removed.
- **The generated artefact currently emits `playbackState: string` / `displayMode: string` on `TemporalSlice` instead of the enum types**: The generated TypeScript in `shared/schemas/src/generated/typescript/types.ts` (lines 1807, 1809) types these slice fields as `string` rather than `PlaybackStateEnum` / `DisplayModeEnum`. This is a generator-emission quirk in the existing artefact, not a LinkML-source issue (the YAML uses `range: PlaybackStateEnum` / `range: DisplayModeEnum`). If the migration finds that consumers cannot narrow on these fields without a cast, the plan phase MUST either resolve the generator emission or ship a thin type-guard helper so consumer code does not need `as PlaybackStateEnum` casts at read sites.
- **Pydantic `TemporalSlice.playbackState: PlaybackStateEnum` default field**: The generated Pydantic model already types the field correctly as the enum. Python-side consumers therefore do not need any migration beyond removing hand-typed Python copies if any exist (none observed at the time of writing). This edge case is an **asymmetry** the plan phase should confirm rather than ignore.
- **IPC message shapes on the host-webview boundary**: `TemporalDisplayModeMessage` in `apps/vscode/src/views/activityPanelView.ts` (lines 47–49) declares `payload: { mode: 'full' | 'trail' }` as a hand-written discriminated-union literal. This message shape MUST be retyped to use `DisplayModeEnum` so the vocabulary match is enforced by the type system, not by the translator that the migration deletes.
- **`shared/components/src/TimeController/types.ts` re-exports `DisplayMode` from `../utils/types`**: The re-export line (`export type { DisplayMode };`) must be removed or retargeted at the generated enum to avoid two local-alias paths resolving to different types during the transition.
- **Roundtrip through JSON serialisation**: Values of both enums MUST survive Python → JSON → TypeScript → JSON → Python roundtrips byte-identically (the existing schema round-trip contract applied to the two new canonical enums).

## Requirements *(mandatory)*

### Functional Requirements

**Schema definition**

- **FR-001**: The LinkML master schema MUST retain the class-level name `PlaybackStateEnum` with permissible values `stopped`, `playing`, `paused` (no changes required — this enum is already canonical at `shared/schemas/src/linkml/session-state.yaml` lines 24–32).
- **FR-002**: The LinkML master schema MUST update `DisplayModeEnum` so that its permissible values are `full` and `trail`, replacing the current `normal` and `snailTrail`. The enum's `description` fields MUST be updated in step so the generated TS docstrings describe "full track" and "trail to current time" rather than "standard track display" and "recent positions".
- **FR-003**: The LinkML `description` on `PlaybackStateEnum` MUST carry a short, UI-agnostic cross-reference to the ADR rather than embedding UI-specific rendering language. Concretely: the schema description MUST mention that component consumers treat `stopped` as equivalent to `paused` (one sentence) and MUST cite the ADR location (`See ADR-NN in docs/project_notes/decisions.md`), but MUST NOT name UI elements (play button / pause button / playhead etc.) — those details belong in the ADR, not in the schema that sits beneath services (review decision 7A; Article IV separation of services from UI).
- **FR-004**: The LinkML class `TemporalSlice` MUST continue to reference `PlaybackStateEnum` and `DisplayModeEnum` as the `range` of its `playbackState` and `displayMode` attributes (no source-side change required; this preserves the Pydantic emission).

**Code generation and derived artefacts**

- **FR-005**: The Pydantic, JSON Schema, and TypeScript generators MUST emit `PlaybackStateEnum` and `DisplayModeEnum` with the canonical permissible values using only existing generator capabilities (no generator upgrade).
- **FR-006**: The generated TypeScript artefact (`shared/schemas/src/generated/typescript/types.ts`) MUST emit the two enums in a form consumers can use to narrow (native TS `enum`, or string-literal union) and MUST expose them via the `@debrief/schemas` package barrel.
- **FR-007**: The generated TypeScript MUST type `TemporalSlice.playbackState` as `PlaybackStateEnum` (or the equivalent string-literal union) and `TemporalSlice.displayMode` as `DisplayModeEnum` — not as `string`. If the current generator emits `string` (as observed at lines 1807, 1809 of the existing artefact), the plan phase MUST choose one of: (a) configure the generator to emit the enum type, (b) upgrade the generator, or (c) ship a post-generation patch step; in all cases the committed artefact MUST carry the enum-typed field.
- **FR-008**: The schema adherence test suite MUST include at least one valid-fixture case per permissible value (`full`, `trail`, `stopped`, `playing`, `paused`) and at least one invalid-fixture case per enum (e.g., legacy `'snailTrail'` and a typo such as `'palying'`) to protect against regression and silent vocabulary drift.
- **FR-009**: All generated derived artefacts committed to the repository MUST be regenerated in the same change set so that the repo remains in a consistent "schema ↔ generated" state after merge.

**Load-boundary validation**

- **FR-023a**: `services/session-state/src/persistence/load.ts` MUST validate the inbound `temporal.displayMode` and `temporal.playbackState` values against the generated enum's permissible values at the load boundary. Unknown values (including legacy `'normal'` / `'snailTrail'`) MUST cause `loadSessionState` to return a `LoadResult` with `success: false` and an `error` string that names the offending field and its observed value (matching the existing `LoadResult` return-based convention at `load.ts:15-22` and the existing version-compatibility error paths at `load.ts:49, 56, 267`). Silent acceptance of legacy or out-of-spec values is forbidden (Article I.3). The validation MUST NOT introduce a throwing error class; doing so would diverge from the module's established contract with its callers (Electron loader, VS Code extension) who expect a resolved `Promise<LoadResult>`.
- **FR-023b**: The two `as never` casts in `services/session-state/src/persistence/load.ts` — line 117 (`setStepSize(temporal.stepSize as never)`) and line 123 (`setDisplayMode(temporal.displayMode as never)`) — MUST be replaced with the typed setter calls once FR-023a's validation has narrowed the runtime value to the canonical type (review decision 1A + D2; Article XV strict-type-safety closure for these two sites). Other `as`-style coercions in `load.ts` (parse-boundary narrowing at lines 62, 64, 98, 103–113, 138, 140–141, 194, 229–232) remain out of scope for this feature.

**Component-side `stopped` rendering rule**

- **FR-023**: `shared/components/src/TimeController/PlaybackControls.tsx` MUST render `playbackState === 'stopped'` identically to `playbackState === 'paused'` (static playhead, play button enabled, pause button disabled or no-op). The `isPlaying` derivation on line 24 (`playbackState === 'playing'`) already implicitly satisfies this — the spec elevates it to an explicit requirement to prevent regression if future code introduces a third branch.
- **FR-024**: `shared/components/src/TimeController/useTimePlayback.ts` MUST either (a) widen its internal `playbackState` state to the three-value `PlaybackStateEnum` and treat `stopped` as equivalent to `paused` in the animation tick (line 91: `if (playbackState !== 'playing' || !timeExtent) return;`), or (b) document why the hook deliberately narrows to two states for internal use while its public surface accepts three. The choice MUST be documented in a single-line comment referencing the ADR.
- **FR-025**: No component-side consumer MUST throw, hang, or enter an unreachable branch when handed `playbackState === 'stopped'` for the first time. Any `switch` or `if/else if` that implicitly assumed two states MUST be audited and either updated or given an explicit `default` branch with the documented `stopped ≡ paused` treatment.

**Drift-prevention and governance tooling**

- **FR-031**: A guard script at `scripts/check-no-hand-typed-temporal-enums.sh` MUST be added, wired into `task lint` via `Taskfile.yml`, and MUST fail the lint step when a hand-written `type DisplayMode`, `type PlaybackState`, or a translation ternary between legacy and canonical `DisplayMode` vocabularies reappears outside `shared/schemas/src/generated/`. The script follows the shape and wiring of the existing `scripts/check-no-geojson-feature.sh` (from feature #204 / #214) — bash + `task lint` entry (review decision D1; durable closure of SC-001/SC-002 beyond the PR merge window).
- **FR-032**: A cross-reference convention for LinkML descriptions MUST be adopted: LinkML `description` fields that cite an ADR MUST use the form `See ADR-NN in docs/project_notes/decisions.md` (uppercase `ADR-`, two-digit number matching the entry heading in `decisions.md`). A companion guard script at `scripts/check-adr-refs.sh` MUST be added, wired into `task lint`, and MUST fail when a LinkML description cites an ADR ID that does not resolve to an `## ADR-NN` heading in `docs/project_notes/decisions.md`. The script follows the same bash + Taskfile.yml wiring as FR-031 (review decision D3; machine-readable traceability for schema ↔ ADR links per Article VIII).

**Governance and traceability**

- **FR-026**: The project MUST capture a dated Architectural Decision Record entry in `docs/project_notes/decisions.md` that (a) names the four deleted hand-typed declarations and their drifted vocabularies, (b) records that `DisplayModeEnum = {full, trail}` and `PlaybackStateEnum = {stopped, playing, paused}` are the canonical vocabularies, (c) records the rationale for choosing the component UI vocabulary (`full|trail`) over the legacy session-state vocabulary (`normal|snailTrail`), (d) records the `stopped ≡ paused` component rendering rule **with the UI-element detail that FR-003 moves out of the LinkML description** (static playhead, play button enabled, pause button disabled / no-op), and (e) links to this spec. The ADR heading MUST use the format `## ADR-NN: Schema-Rooted DisplayMode and PlaybackState — 2026-04-21` where `NN` is assigned during implementation; the LinkML `PlaybackStateEnum` description cites this ADR via FR-032's convention.
- **FR-027**: The change MUST pass the CI verify pipeline (lint, typecheck, tests — including schema adherence tests, the new regen-idempotency pytest, both new guard scripts, and Playwright E2E covering TimeController) on a single PR, so that the schema rename, regeneration, migration, and governance tooling are reviewed and merged atomically.

### Key Entities

- **`DisplayModeEnum`** *(LinkML enum, renamed in this feature)*: The two permissible values for track visualisation. Canonical vocabulary after this feature: `full` (render the entire track regardless of current time) and `trail` (render a snail-trail from track start up to current time). Replaces the drifted pair (component-side `'full'|'trail'` vs session-state-side `'normal'|'snailTrail'`) with a single generated enum.
- **`PlaybackStateEnum`** *(LinkML enum, unchanged shape, widened adoption)*: The three permissible values for time playback state — `stopped`, `playing`, `paused`. Already defined in LinkML with these values; this feature removes the hand-typed two-value component copy and the three-value session-state copy, so both sides speak the generated enum.
- **`TemporalSlice`** *(existing LinkML class, unchanged shape)*: Carries `playbackState: PlaybackStateEnum` and `displayMode: DisplayModeEnum`. This feature does not change the slice's attributes; it only guarantees (via FR-007) that the generated TS emits the fields with enum types rather than plain `string`.
- **`TemporalDisplayModeMessage` + sibling IPC shapes** *(existing IPC message shapes, retyped — review 2A)*: IPC messages crossing the VS Code host ↔ webview boundary. Today hand-declared with narrowed string unions: `TemporalDisplayModeMessage.payload.mode: 'full' | 'trail'` (`activityPanelView.ts:47-49`); `PlaybackStateChangeMessage.state: 'playing' | 'paused'` and `DisplayModeChangeMessage.mode: 'full' | 'trail'` (`timeRangeView.ts:28-34`); `SetDisplayModeMessage.displayMode: 'full' | 'trail'` (`webview/messages.ts:123-127`). All retyped to `DisplayMode` / `PlaybackState` so vocabulary matches are enforced by the type system at every message-bus crossing.
- **`timeRangeView.ts` callback + method types** *(existing, widened — review 2A)*: Private callback fields `_onPlaybackStateChangeCallback` / `_onDisplayModeChangeCallback` (lines 64–65) and public methods `onPlaybackStateChange` / `onDisplayModeChange` (lines 322, 329) currently declare narrow string-literal unions. Widened to `PlaybackState` / `DisplayMode` so the public API of the view surface is vocabulary-aligned.
- **Deleted silent-narrowing translator** *(review 3A)*: The `state.setPlaybackState(message.state === 'playing' ? 'playing' : 'paused')` ternary at `apps/vscode/src/views/timeRangeView.ts:241`. Pre-change, it silently collapsed any non-`'playing'` value (including a legitimate `'stopped'`) to `'paused'` in session-state. Post-change, it is a direct pass-through: `state.setPlaybackState(message.state)`.
- **Load-boundary validation for persisted session state** *(review 1A + D2)*: `services/session-state/src/persistence/load.ts` lines 117 and 123. Pre-change, both fields are piped through `as never` casts — a runtime-unchecked escape hatch that silently accepts any value. Post-change, both fields are validated against the generated enum permissible-value set before the store is mutated; legacy `'normal'` / `'snailTrail'` / unknown playback states are rejected with a typed error.
- **Drift-prevention and ADR-ref guard scripts** *(review D1 + D3)*: Two new bash scripts under `scripts/` wired into `task lint`. `check-no-hand-typed-temporal-enums.sh` fails if a `type DisplayMode` / `type PlaybackState` or legacy translation ternary reappears outside generated artefacts. `check-adr-refs.sh` fails if a LinkML description cites an ADR ID that does not resolve to a heading in `docs/project_notes/decisions.md`. Both follow the shape and wiring of the existing `scripts/check-no-geojson-feature.sh` established by features #204/#214.
- **Deleted hand-typed `DisplayMode` (×2)**: The declaration at `shared/components/src/utils/types.ts:80` (`'full' | 'trail'`) and at `services/session-state/src/types/temporal.ts:110` (`'normal' | 'snailTrail'`). Both are retired; consumers import `DisplayModeEnum` from `@debrief/schemas`.
- **Deleted hand-typed `PlaybackState` (×2)**: The declaration at `shared/components/src/TimeController/types.ts:17` (`'playing' | 'paused'`) and at `services/session-state/src/types/temporal.ts:105` (`'stopped' | 'playing' | 'paused'`). Both retired; consumers import `PlaybackStateEnum` from `@debrief/schemas`.
- **Deleted translator helpers**: `toComponentMode` and `toStoreMode` in `apps/web-shell/src/App.tsx` plus the six inline DisplayMode-translation ternaries spread across `apps/vscode/src/views/activityPanelView.ts`, `apps/vscode/src/views/timeRangeView.ts`, and `apps/vscode/src/webview/mapPanel.ts`. All removed; both sides now speak the same vocabulary.

## Assumptions

- **Component UI vocabulary wins for `DisplayModeEnum`**: The idea doc (`docs/ideas/205-displaymode-playbackstate-linkml.md`) explicitly proposes `full|trail` as the canonical vocabulary. This spec carries that choice forward because (a) the user-facing toggle buttons literally read "Full" and "Trail" in `shared/components/src/TimeController/DisplayModeToggle.tsx`, so the vocabulary is already the one reviewers see in the UI, and (b) the session-state-side `normal|snailTrail` vocabulary was an internal-only artefact that never reached the user. The renaming cost (one LinkML enum value-list edit plus default-value changes) is contained; the user-visible text on the toggle buttons does not change.
- **Session-state superset vocabulary wins for `PlaybackStateEnum`**: Session-state's three-state vocabulary is already canonical in LinkML. The component layer widens by adopting it and treating `stopped` identically to `paused` during rendering (FR-023 – FR-025).
- **No persisted session-state JSON in the wild requires a backwards-compat shim**: A full-tree search for `"displayMode"` in `.json` files at the time of spec writing returned no matches. Any future writes through `DEFAULT_TEMPORAL_SLICE` would have been `"normal"`; the feature ships in a single PR that regenerates fixtures in step, so there is no installed base of out-of-repo files that we need to accommodate. If the plan phase discovers fixtures added between now and merge, they are migrated in-place (idea-doc bullet 3 confirms this approach).
- **Python-side `PlaybackStateEnum` / `DisplayModeEnum` consumers need no migration beyond regeneration**: The generated Pydantic model already types `TemporalSlice.playbackState` and `TemporalSlice.displayMode` with the correct enum. No hand-typed Python copies were observed at the time of writing. The feature's Python surface area is therefore limited to the schema change, regeneration, and fixture additions — it does not require edits to `services/session-state`, `services/stac`, or `services/calc` unless the plan phase discovers an overlooked consumer.
- **Storybook and Playwright tests exercise the migrated types**: The tests at `shared/components/src/TimeController/useTimePlayback.test.ts`, `shared/components/src/TimeController/TimeController.test.tsx`, `shared/components/src/TimeController/TimeController.stories.tsx`, `apps/web-shell/playwright/tests/time-controller.spec.ts`, and `apps/web-shell/playwright/tests/undo-redo-split.spec.ts` are the de-facto regression suite for this consolidation. The plan phase MUST confirm that the migrated code passes them without behavioural change; any asserted behaviour around `stopped` treatment should become an explicit test case.
- **Generator capability for the correct `TemporalSlice` field emission**: The existing LinkML → TypeScript generator already emits `PlaybackStateEnum` and `DisplayModeEnum` as declared classes (visible at lines 393–411 of the generated artefact), but emits `TemporalSlice.playbackState` and `TemporalSlice.displayMode` as `string` at lines 1807 and 1809. The spec assumes this is a tractable generator-configuration or post-processing concern — not a LinkML source-side defect — and that the plan phase can resolve it without a generator upgrade. If upgrade proves necessary, it is recorded in `research.md` during the plan phase.
- **Idempotent regeneration**: Regenerating Pydantic and TypeScript from the updated LinkML schema is deterministic — two runs on the same input produce byte-identical output. This lets CI guard against drift between the checked-in artefact and the source schema.
- **No behavioural changes to runtime code outside the documented `stopped` rule**: This is primarily a type-level and vocabulary consolidation. Playback animation, transport controls, display-mode rendering, and session-state updates behave identically to before, except that component consumers of `playbackState` now explicitly handle `stopped` (and do so identically to `paused`, so there is no user-observable behaviour change).

## Out of Scope

- **Introducing additional permissible values to either enum**: `DisplayModeEnum` stays at two values; `PlaybackStateEnum` stays at three values. Future enum extensions (e.g., a `buffering` playback state, a `blended` display mode) are separate features.
- **Renaming or restructuring `TemporalSlice`, `TimeFilter`, `TimeRange`, or `TimeStep`**: These classes are untouched by this feature. The `camelCase` vs `snake_case` drift comment that exists elsewhere in `services/session-state/src/types/` is not addressed here.
- **Consolidating `TimeInstant`, `PlaybackSpeed`, `UIState`, or `TimeUnitEnum`**: `TimeInstant` already has a deliberately-documented non-migration note in `services/session-state/src/types/temporal.ts`; `PlaybackSpeed` is a component-local numeric alias; `UIState` is a component-local string literal; `TimeUnitEnum` is already LinkML-sourced. None are in scope.
- **Deprecating the LinkML `normal` and `snailTrail` values with a migration period**: No staged deprecation — the values are renamed atomically in the same PR that migrates consumers, because the search above found no installed-base fixtures and the feature is sized to ship as a single atomic change.
- **Sweeping all remaining `as` coercions in `services/session-state/src/persistence/load.ts`**: The review expands the feature to the two `as never` casts at lines 117 and 123 (FR-023a/b). Other coercions in the file (parse-boundary narrowing for `currentTime`, `TimeRange.start`/`.end`, `featureCollectionUri`, `selection`, `Coordinate` narrowing helpers on lines 194 and 229–232) have legitimate uses and remain out of scope — a broader `load.ts` hardening pass is a separate design decision.
- **Auditing non-LinkML type declarations more broadly**: Backlog item #206 (`[E11] Audit non-LinkML type declarations`) owns the broader sweep. This feature addresses only the two enums named in #205.
- **Changing the VS Code `debrief.setDisplayMode` command signature or the `message.payload` wire formats beyond the typing change**: The message shapes' values change from translated-strings to raw-enum-strings, but that is a one-for-one value substitution (`'full'` ↔ `'full'`, `'trail'` ↔ `'trail'`). No new fields, no new message kinds, no protocol-version bump.
- **Coordinating the LinkML-regen PR sequencing with any concurrently-in-flight LinkML work**: Items #203 and #204 have shipped (status `complete`); this feature is independent. Practical rebase-of-generated-artefacts concerns remain the implementing developer's problem at PR time — they are not a spec requirement.
