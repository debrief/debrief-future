# Implementation Plan: Log Recording Service

**Branch**: `071-log-recording-service` | **Date**: 2026-02-09 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/071-log-recording-service/spec.md`
**Epic**: E02 -- PROV Logging Implementation (Phase 1)

## Summary

Implement a TypeScript Log Service module within the `session-state` package that automatically records every successful tool execution as a PROV-aligned Log entry on affected features. The service provides two core functions: `recordToolResult()` wraps a ToolResult in Log entries and writes them to features' `properties.provenance[]` arrays via stacService; `getTimeline()` assembles a global timeline by collecting, deduplicating, and sorting entries from all features. Integration with the existing tool execution command (`executeTool.ts`) is transparent to the analyst. Dirty tracking triggers through explicit `markDirty()` calls after provenance writes.

## Technical Context

**Language/Version**: TypeScript 5.x (Log Service, type updates, VS Code extension, web-shell)
**Primary Dependencies**: Zustand ^5.0.0 (session-state store), existing stacService (file I/O), existing calcService (MCP parsing). No new external dependencies.
**Storage**: Local filesystem -- GeoJSON files within STAC Item directories (read/write via stacService)
**Testing**: Vitest (unit + integration), `createSessionStore()` for isolated store instances
**Target Platform**: VS Code extension (Node.js), web-shell (browser)
**Project Type**: Multi-package monorepo (modifications span `services/session-state`, `apps/vscode`, `apps/web-shell`)
**Performance Goals**: Log recording adds <50ms to tool execution. Timeline assembly for 100 operations across 20 features completes in <100ms.
**Constraints**: Offline-capable (Art. I). No network calls. All file I/O through stacService.
**Scale/Scope**: Typical plot has 5-20 features, 10-100 tool operations per session. Phase 1 handles this scale; snapshot pagination (Phase 4) addresses longer histories.

**Post-design re-check**: All gates pass. The TypeScript Log Service is a considered departure from "domain logic in Python" (Art. IV), justified in the SRD (Annex A.2) and transition plan. The Log is a session-state concern tightly coupled to frontend orchestration; Python services remain stateless data transformers.
