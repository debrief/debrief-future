## Notes

- This is **v2** of the spec for #200, authored after `/speckit.review` accepted four scope-shaping changes: (a) SC-001 / FR-001 narrowed to the generic-GeoJSON call-site family (shared/components's LinkML-typed calculateBounds is explicitly separate); (b) User Story 4 added, folding the `mapPanel.ts::fitToSelection()` rewrite into scope and fixing a pre-existing silent-miss bug for non-Point/non-LineString selections; (c) FR-007 added, requiring an explicit, reviewable narrowing gate for the widened parameter's untyped portion (Article XV.5); (d) a supersede decision recorded for `origin/200-bounds-consolidation` (commits `b55c1d7e`, `38c2170c`).
- The spec references TypeScript-specific concepts (`as`-cast, `any`, `unknown`) in FR-007 and SC-009. These are not implementation-detail leakage in a leakage-to-avoid sense — they are the necessary language in which the narrowing-gate requirement can be expressed testably. The project is a TypeScript + Python monorepo; the narrowing-gate's verbal form ("no untyped data reaches application code") would be unverifiable. The TypeScript-specific wording is the minimum needed to make FR-007 / SC-009 pass the "testable and unambiguous" criterion.
- "UI Feature Validation" section deliberately omitted — this is a non-UI tech-debt feature. The UI surface (the map's zoom behaviour) is exercised behaviourally via user stories, not via screen progression or decision inputs.
- Four deferred items are named in the "Out of Scope" section and will be added as BACKLOG.md entries during the implementation phase of this spec: drift-prevention rule, shared/components unification, LinkML-ify SafeFeature/GeoJSONFeature, and pre-computed-bbox fast-path.
- Downstream artefacts (plan.md, research.md, data-model.md, contracts/, quickstart.md, media/) were removed at skeleton commit `42b85a6a` because they were based on v1 and would mislead. They will be regenerated by the next `/speckit.plan` run against this v2 spec.
